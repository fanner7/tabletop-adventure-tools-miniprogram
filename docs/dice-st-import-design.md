# 骰娘 .st 角色卡导入 — 设计文档

> 设计文档 · 2026 · 桌面冒险工具集
> 目标：COC 调查员工具与守密人工具的「导入角色」接受骰娘数据结构（海豹骰 Sealdice / 塔塔等兼容的 .st 格式），数据构造与 `coc7-gen generateDiceImport`（骰娘导出）同构。
> **实现状态：已实现（utils/dice-st.js + coc7-gen 三通道导入 + coc-keeper 三通道导入 + 单元测试）。**

---

## 1. 背景

玩家在建卡工具 / 骰娘里维护的角色，常以 .st 文本形式存在（群聊、骰娘指令、其他工具导出）。此前两个工具的导入只认 JSON / C7C1 角色码，玩家需要重新手工录入。本次为导入增加 .st 通道，格式构造参照本工具自己的骰娘导出（`generateDiceImport`），保证「自己导出的文本自己导得回」。

## 2. .st 格式（构造参照骰娘导出）

```
.st <角色名>-力量60 敏捷70 意志80 体质65 外貌55 教育85 体型62 智力75 幸运50 hp12 理智80 mp16 会计45 斗殴25 手枪20 写作5 ...
```

| 条目 | 含义 | 说明 |
|---|---|---|
| `.st ` | 指令前缀 | 海豹骰/塔塔通用；解析时剥离 |
| `<角色名>-` | 角色名 | 名字为第一个含 `-` 的 token 之前部分 + 破折号前内容（名字可含空格） |
| 力量/敏捷/意志/体质/外貌/教育/体型/智力/幸运 | 九属性 | 映射 str/dex/pow/con/app/edu/siz/int/luck |
| `hp` / `理智` / `mp` | 衍生值 | 小写 hp/mp（与导出一致），兼容 `san` 别名；解析为游玩 HP/SAN/MP 当前值 |
| `技能名+总值` | 技能 | 会计45、母语85 等；专攻技能导出专攻名：斗殴→格斗①、手枪→射击①、写作→技艺①、拉丁语→外语① |

已知导出端限制（不影响解析）：骰娘导出的 skillOrder 不含 外语①/②/③、格斗②/③、技艺③，这些技能不会出现在 .st 文本中；.st 本身无职业、无点表拆分、无武器、无文本块。

## 3. 解析规则（utils/dice-st.js）

### 3.1 技能名解析优先级（resolveSkill）

1. **精确技能名**：`药学`/`人类学`/`心理学` 等先按独立技能匹配（它们同时也是「科学」的专攻选项名，精确优先防撞车）；
2. **括号专攻语法**：`格斗(斗殴)25`、`技艺①（写作）25`、`驾驶(汽车)25`（海豹骰常见变体，半/全角括号均可）；槽位归一化后带专攻定义则括号内文本为专攻，无专攻定义（如 `母语(中文)`）则忽略括号；
3. **别名**：`FREE_SKILL_ALIAS`（汽车驾驶→驾驶①、打字→技艺① 等）；别名目标带专攻时原名作为专攻文本（`汽车驾驶` → `驾驶①（汽车驾驶）`）；
4. **options 型专攻**：按技能表顺序找首个同名选项（斗殴→格斗①、手枪→射击①、数学→科学（数学））；
5. **text 型专攻启发式**：语言名（拉丁语/英语/法语…）→ 外语①；驾驶术语（飞行器/船/卡车…）→ 驾驶①；其余 → 技艺①（保留总值可编辑，用户可自行改名）；
6. 无匹配则**归入技艺①**（未知自定义技能如「驯鹰」→ `技艺①（驯鹰）`，总值保留，不静默丢失）。

### 3.2 数值重建

- **技能总值 = 基础值 + 兴趣点**：.st 只有总值，无点表拆分 → 全部点数记入**兴趣点**（intPts），基础值由表内规则反推（母语=EDU、闪避=DEX/2、专攻子项 base）；
- **钳位**：总值低于表内基础值时按基础值显示（钳 0 点），避免负点；
- **点预算**：`usedIntPoints = Σ intPts`，`totalIntPoints = max(INT×2, used)`——外部卡可能超 INT×2 预算，取 max 避免编辑被超支校验阻塞；
- **职业为空**：.st 无职业信息 → `selectedOcc` 缺省、`occPts` 空、技能页全部按兴趣技能编辑；
- **产物结构**：与 C7C1 解码产物同构（含 attrDisplay/derived/derivedItems/sortedSkillsByCat 显示字段重建，复用 char-codec 共享 helper），coc7-gen 与 coc-keeper 均直接消费。

### 3.3 健壮性

- 剥离 `.st` 前缀（大小写不敏感），容忍全/半角空格、多余空白、名字含空格；
- 容忍冒号分隔变体（`力量:60`、`hp:12`）；
- 属性/衍生值重复条目取首个；无法识别的 token 静默跳过；
- 没有任何可识别条目（无属性也无技能）→ `FORMAT` 错误，导入端提示「不是有效的调查员数据」。

## 5. 测试（tools/test/dice-st.test.js）

- 骰娘导出文本往返：名字/九属性/hp·san·mp/全部导出技能总值逐项一致/专攻解析；
- 手写 .st：属性映射、hp·理智·mp、options 专攻、text 启发式（拉丁语→外语①）、别名（汽车驾驶→驾驶①）、未知技能归入技艺①；
- 撞车场景：药学/人类学/心理学 精确名优先；
- 钳位：总值低于基础值；
- 未命名 / 空 / 乱文本拒绝；
- 集成：coc7-gen 导入 .st 入库并可编辑；coc-keeper 导入 .st 渲染字段就绪。

## 6. 已知限制（.st 固有信息缺失）

- 无职业/年龄/时代/性别 → 用默认值（25 岁/男/1920s），职业为空；
- 点表拆分不可知 → 全部记入兴趣点；
- 专攻槽位为最佳匹配（精确名 > options > 启发式），极端情况下显示名可能与源卡不同（总值始终保留）；
- 外语①/②/③、格斗②/③、技艺③ 不被骰娘导出携带（导出端既有行为），导入后按基础值显示。
